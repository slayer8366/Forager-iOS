## 1. Design

### Sources read today (2026-11-18)

- XcodeGen's spec format at the pinned tag: `https://raw.githubusercontent.com/yonaskolb/XcodeGen/2.46.0/Docs/ProjectSpec.md`
  (1,305 lines, saved as `scratchpad/s81/web/ProjectSpec.md`). Used: Target `info` (`:382`, generates the Info.plist and
  sets `INFOPLIST_FILE`, and fills `CFBundleIdentifier` and `CFBundleExecutable` itself), `preBuildScripts` (`:399`,
  "run *before* any other build phases"), Build Script `basedOnDependencyAnalysis` (`:822`, defaults to `true`),
  `options.deploymentTarget` (`:143`), top-level `schemes` (`:990`).
- The setting presets inside the pinned zip (`xcodegen/share/xcodegen/SettingPresets/`): `Platforms/iOS.yml` gives
  `SDKROOT: iphoneos`, `TARGETED_DEVICE_FAMILY: '1,2'`, `LD_RUNPATH_SEARCH_PATHS`; `base.yml` gives `SWIFT_VERSION: '5.0'`
  and `PRODUCT_NAME: $(TARGET_NAME)`.
- Kotlin's direct-integration page, `https://kotlinlang.org/docs/multiplatform/multiplatform-direct-integration.html`
  (page dated 01 October 2026): the Run Script (the `OVERRIDE_KOTLIN_BUILD_IDE_SUPPORTED` guard, then `cd` to the
  project root, then `./gradlew :<module>:embedAndSignAppleFrameworkForXcode`); "Disable Based on dependency analysis";
  the phase before Compile Sources; User Script Sandboxing disabled. The page says nothing about framework search paths
  or linker flags.
- Kotlin 2.3.10's `AppleXcodeTasks.kt` (`https://raw.githubusercontent.com/JetBrains/kotlin/v2.3.10/libraries/tools/kotlin-gradle-plugin/src/common/kotlin/org/jetbrains/kotlin/gradle/plugin/mpp/apple/AppleXcodeTasks.kt`):
  the framework is assembled under `build/xcode-frameworks/<frameworkSearchDir>` (`:419`) and symlinked into Xcode's
  `BUILT_PRODUCTS_DIR` (`:243-263`); the embed task is disabled for a static framework (`:270`, `{ !framework.isStatic }`);
  a check task fails the build if `ENABLE_USER_SCRIPT_SANDBOXING` is on (`:371`).
- JetBrains' own Xcode projects, for the settings the page omits: `Kotlin/KMP-App-Template` (`main`,
  `iosApp/iosApp.xcodeproj/project.pbxproj:324-327`, a static framework, `isStatic = true` in `shared/build.gradle.kts:19`)
  sets `FRAMEWORK_SEARCH_PATHS` to `$(SRCROOT)/../shared/build/xcode-frameworks/$(CONFIGURATION)/$(SDK_NAME)` and no
  `OTHER_LDFLAGS`; `JetBrains/compose-multiplatform-ios-android-template` (`main`, `:317-331`) sets the same search path
  and `OTHER_LDFLAGS` with `-framework` entries. Its Info.plist (`iosApp/iosApp/Info.plist` in the first) carries
  `CADisableMinimumFrameDurationOnPhone`, `UIApplicationSceneManifest`, `UILaunchScreen`, `LSRequiresIPhoneOS`.

### Files

- `iosApp/project.yml` (XcodeGen 2.46.0): project `ForagerApp`, `options.deploymentTarget.iOS: "16.0"` (provisional,
  RECORD -201 T11); one target `ForagerApp`, `type: application`, `platform: iOS`, sources `ForagerApp/`.
  - `info`: path `ForagerApp/Info.plist` (generated on the runner, not committed), properties `CFBundleDisplayName:
    Forager dev`, `CFBundleShortVersionString: "0.0.1"`, `CFBundleVersion: "1"`, `LSRequiresIPhoneOS: true`,
    `UILaunchScreen: {}` (without a launch screen key an iOS app runs letterboxed; inferred from Apple's documented
    behaviour, not seen), `UIApplicationSceneManifest` with `UIApplicationSupportsMultipleScenes: false`,
    `CADisableMinimumFrameDurationOnPhone: true` (Compose Multiplatform checks for this key at start-up; inferred from
    JetBrains' templates carrying it, the check itself not read today), portrait and both landscape orientations.
    `CFBundleIdentifier` is generated by XcodeGen as `$(PRODUCT_BUNDLE_IDENTIFIER)`.
  - `settings.base`: `PRODUCT_BUNDLE_IDENTIFIER: com.zynergylabs.forager.ios.dev`, `CODE_SIGNING_ALLOWED: NO`,
    `ENABLE_USER_SCRIPT_SANDBOXING: NO`, `FRAMEWORK_SEARCH_PATHS: $(inherited) $(SRCROOT)/../app/build/xcode-frameworks/$(CONFIGURATION)/$(SDK_NAME)`,
    `OTHER_LDFLAGS: $(inherited) -framework ForagerApp`. The identifier and the display name carry a comment: placeholders,
    RECORD -202.
  - `preBuildScripts`: one phase "Compile Kotlin Framework", `basedOnDependencyAnalysis: false`, the documented script
    with `$SRCROOT/..` as the root and `:app` as the module. One addition: `--console=plain` on the `./gradlew` line, so the
    task headers land in the `xcodebuild` log in a form the check can grep.
  - `schemes.ForagerApp`: build target `ForagerApp: all`, run config Debug, so `xcodebuild -scheme ForagerApp` does not
    depend on Xcode auto-creating a scheme.
- `iosApp/ForagerApp/ForagerApp.swift`: `@main struct ForagerAppMain: App` with a `WindowGroup` holding `ComposeView()
  .ignoresSafeArea()`, and `ComposeView: UIViewControllerRepresentable` returning `MainViewControllerKt.MainViewController()`
  (the Kotlin file `MainViewController.kt` makes the class `MainViewControllerKt`; inferred from Kotlin/Native's naming
  of top-level functions, shown by the Swift compile).
- `iosApp/.gitignore`: the generated `ForagerApp.xcodeproj/` and `ForagerApp/Info.plist`.
- `.github/workflows/app.yml`: **a new job `app-bundle`**, not the `app-framework` job extended. Why: in the same job the
  link task would already be up to date when the Run Script asks Gradle for it, so the job could not show that Gradle
  linked the framework from inside `xcodebuild`; A1-1's job and its checks stay exactly as they ran. Cost: a second cold
  Kotlin/Native download and link per run (about 3 to 4 minutes of macOS time, from A1-1's job `134577660279`). Steps:
  checkout and Temurin `21.0.13+9` (same pins as the other jobs); select Xcode 26.0.1 and print `xcodebuild -version`;
  fetch XcodeGen 2.46.0 with `tools/fetch-pinned.sh` (URL, size 4278764 and SHA-256 `4d9e34b6...6806`, re-downloaded
  and re-checked today with the same script: "matches its pins"), unzip, print `xcodegen --version`, `xcodegen generate
  --spec iosApp/project.yml`; `xcodebuild` as in pre-build section 5 (`-project iosApp/ForagerApp.xcodeproj -scheme
  ForagerApp -configuration Debug -sdk iphonesimulator -destination 'generic/platform=iOS Simulator' -derivedDataPath
  build/xcode ARCHS=arm64 CODE_SIGNING_ALLOWED=NO build`), log `tee`'d to `build/xcodebuild.log`, timed; the checking
  step; the artifact `a1-2-xcode` (the generated `.xcodeproj`, `build/xcodebuild.log`, the built app's Info.plist) with
  `if: always()`, `actions/upload-artifact` pinned to `cf430e030ddbb5b0abf93d22962f4752f3646cd9` as `brouter.yml` pins it.
  Path triggers gain `iosApp/**` and `tools/fetch-pinned.sh` (pre-build T5 lists both).
- **The checking step fails unless** all of: (a) `build/xcode/Build/Products/Debug-iphonesimulator/ForagerApp.app` is a
  directory; (b) `plutil -extract CFBundleIdentifier raw` on its Info.plist prints exactly `com.zynergylabs.forager.ios.dev`
  and `CFBundleDisplayName` exactly `Forager dev` (and `plutil -p` is printed whole); (c) `lipo -info` on the
  executable `ForagerApp.app/ForagerApp` names `arm64`; (d) the `xcodebuild` log holds `> Task :app:linkDebugFrameworkIosSimulatorArm64`
  with no outcome suffix, i.e. Gradle linked the framework from inside `xcodebuild` in this job. (d) is mine, beyond the
  brief's three: it is what tells the Run Script path from the fallback.

## 2. Predictions (written before any build file changed)

- Q1. `fetch-pinned.sh` prints `xcodegen-2.46.0.zip: fetched from https://github.com/yonaskolb/XcodeGen/releases/download/2.46.0/xcodegen.zip, matches its pins (4278764 bytes, SHA-256 4d9e34b6...)`.
- Q2. `xcodegen --version` prints `Version: 2.46.0`; `xcodegen generate` prints that it loaded the spec and created
  `ForagerApp.xcodeproj` (exact wording not known).
- Q3. `xcodebuild -version` prints `Xcode 26.0.1` and `Build version 17A400` (as in A1-1's job).
- Q4. `xcodebuild` ends `** BUILD SUCCEEDED **`; inside its log, the Run Script phase's Gradle output, with
  `> Task :app:linkDebugFrameworkIosSimulatorArm64` (plain), `> Task :app:embedAndSignAppleFrameworkForXcode` and
  Gradle's `BUILD SUCCESSFUL`.
- Q5. The check prints `plutil -p` with `"CFBundleIdentifier" => "com.zynergylabs.forager.ios.dev"` and
  `"CFBundleDisplayName" => "Forager dev"`, `lipo -info` saying `Non-fat file: ... is architecture: arm64`, and its OK line.
- Q6. Time: `xcodebuild` 4 to 7 minutes (most of it the Kotlin/Native download and link, as in A1-1: about 1 min 40 s
  of download and unpacking plus about 1 min 24 s of link, plus Gradle configuration and the klib compile); the job 6 to
  9 minutes.
- Q7. Iterations: at least one red run before green is more likely than not (a project nobody has opened, first
  contact between XcodeGen 2.46.0 and Xcode 26.0.1, and Swift's explicit module scanning in Xcode 26 meeting a framework
  that appears only after a build phase; the last is a guess at the likeliest failure, not a known issue).
- Q8. `app-klibs` and `app-framework` print what they printed in run `44237677080` (they are unchanged).
